前言:适用对象与最终成果

这篇教程记录一套完整可复现的王国之泪模拟优化流程。起点是 UltraCam 3.0 mod 手动装好后仍锁 30 帧,终点是 4K 输出 + FSR + 稳定 60fps(Avg 60 / Max 67),而 GPU 占用只有 57%推断。

游戏包为 1.0.0 本体 + 1.4.2 升级包,全程以 1.4.2 为目标版本。其他硬件配置的读者可以照搬流程,只是部分参数(阴影分辨率、渲染距离)需要按自己的余量增减。

第一章 游戏本体与 1.4.2 升级包的正确安装(含转格式教程)

这一章解决"游戏怎么装进 Ryujinx、版本怎么对"的问题,版本不对,后面一切 mod 都是白搭。

1.1 游戏包结构解析

手里的游戏包是标准的"本体 + 升级包"组合:1.0.0 本体(Urbase)+ 1.4.2 升级包(Update)。本体可以独立运行,但升级包不能单独运行,必须作为 Title Update 挂载到本体上已核实UltraCam 官方支持版本表 ↗。所有后续的 mod 都是按 1.4.2 的代码生成的,所以游戏列表里显示的版本必须是 1.4.2,否则 mod 加载不到正确的内存地址,直接失效。

1.2 升级包格式转换(重点)

下载到的升级包不一定能直接喂给模拟器。常见情况是升级包为 xci 整合盘、加密封包或缺少签名的 nsp,Ryujinx 挂载时报校验错误或直接不识别,这时候需要先用 NSC_Builder 转一次格式。

NSC_Builder 是一个开源的 Switch 文件处理工具,支持 nsp/xci 互转、多内容合并、去除 titlerights 加密等操作已核实GitHub 仓库 ↗。操作步骤:

  1. 下载 NSC_Builder,解压后双击 NSCB.bat 启动(需要系统装有 Java)
  2. 选择 File Mode(文件模式)
  3. 按提示输入升级包文件路径
  4. 选择转换目标:xci 转 nsp 选 "merge/extract" 相关功能;nsp 去加密选 "Erase titlerights encryption"
  5. 输出文件保存到一个新目录

转换完成后验证:把输出文件放进 Ryujinx 的游戏目录,刷新游戏列表,右键游戏查看属性,确认升级包能被扫描到且版本号显示 v1.4.2。如果扫描不到,多半是转换模式选错了,换一个输出选项重试。

1.3 Ryujinx 中的导入流程

  1. 本体导入:Options → Add Game Directory,选中放本体的文件夹,游戏出现在列表中
  2. 升级包挂载:右键游戏 → Manage Title Updates → Add → 选中 1.4.2 的 nsp 文件 → 确认版本列表里显示 1.4.2 → Save
  3. 版本核对:游戏列表中该游戏条目右侧的版本号应显示 1.4.2 而非 1.0.0。这一步是后文所有 mod 生效的前提

1.4 常见报错排查

版本号不显示 / 挂载后仍是 1.0.0:升级包没挂上,重新进 Manage Title Updates 检查是否选中了 1.4.2 并 Save;如果挂上了还不对,删掉 games\0100F2C0115B6000\cache\ 后重启模拟器。

NCA 校验失败:升级包文件损坏或签名问题,回到 1.2 节重新转换;反复失败就换源重新下载。

扫描不到升级包:格式问题,参考 1.2 节转格式。

1.5 Ryujinx 基础设置(此处先行锁定)

在装 mod 之前,先把模拟器侧的设置定下来,后面不再动:

  • Resolution Scale:1x——最关键的一条。分辨率缩放由 mod 内部管理,模拟器再放大一层等于把 4K 输出又乘一遍,显存直接爆,帧数崩
  • DRAM:8GB(默认 4GB 偏小,12GB 会挤压系统内存,8GB 最平衡)
  • VSync:Switch / 图形后端:Vulkan / 着色器缓存:开启

第二章 60fps mod(UltraCam 3.0)安装与启用

mod 的正确姿势是"文件放对 → 手动勾选 → 进游戏呼出菜单手动启用",三步缺一不可。

2.1 版本对齐原则

UltraCam 3.0.0 是按游戏 1.4.x 版本生成的,正好匹配 1.4.2,无需任何额外处理已核实官方 Release Notes ↗。这就是第一章坚持把游戏对到 1.4.2 的原因——mod 版本和游戏版本一致,加载才能命中正确的内存地址。

2.2 三个快速检查(5 分钟内定位问题)

装完 mod 后如果没效果,先按顺序做这三个检查,绝大多数问题出在这里:

  1. Manage Mods 手动勾选:手动复制到 mods 文件夹的 mod 不会自动启用,必须在 Ryujinx 中右键游戏 → Manage Mods,把对应的 mod 条目打勾,再 Save
  2. 文件夹结构核查:正确的路径是 mods\contents\0100F2C0115B6000\[mod名]\exefs\subsdk9 + main.npdm(有 romfs 的 mod 还有 romfs 文件夹)。zip 解压时多套一层文件夹是最常见的错误,Ryujinx 会因为找不到 exefs 而静默加载失败
  3. subsdk9 文件大小验证:正常的 subsdk9 在 200KB~2MB 之间。如果文件只有几 KB 甚至 0 KB,说明生成失败,需要用 NX Optimizer 重新生成

2.3 清缓存

切换游戏版本或切换 mod 之后,必须删除 games\0100F2C0115B6000\cache\ 整个文件夹再启动游戏。旧缓存会让新 mod 加载异常,症状是帧数不对或直接崩溃。

2.4 进游戏后手动呼出 UltraCam 菜单,启用 60fps(关键步骤)

已核实这是本次踩坑里最隐蔽的一步:mod 文件层面装好、Manage Mods 里也勾选了,但游戏默认仍以原版 30fps 运行——必须在游戏内呼出 UltraCam 菜单,手动把 60fps 选项打开,mod 才真正生效官方说明 ↗。如果以为"装好 mod 进游戏就自动 60 帧",玩起来还是 30 帧,就会得出"mod 没用"的错误结论。

呼出方式(官方默认键位):键盘按 F12;手柄是 ZL+ZR+左摇杆按下已核实UltraCam API 文档 ↗。

呼出菜单后,进 FPS Settings 标签页:

  • Dynamic FPS:Turn On
  • FPS / Menu FPS / Movie FPS:全部设为 60.000
  • 点 Apply Changes 保存

完整配置参数在第四章有最终版表格,这里先把 60fps 开起来验证 mod 是否生效。

如果菜单呼不出来,检查两件事:一是当前焦点必须在游戏窗口上(点一下游戏画面再按 F12);二是 F12 可能被系统或其他软件占用,在菜单 Settings 里改一个自定义键即可。

2.5 验证清单

三条全过,mod 才算装成:

  • 游戏内帧数显示 60(而非 30)
  • 走路速度正常(不是半速慢放)
  • 不再出现约 45 秒后的空指针崩溃(锁 30 帧时 60fps mod 运行在错误目标上的典型症状)

第三章 被忽略的最大免费优化——XMP 内存超频

这是整个流程里收益最高、代价最低的一步:不花一分钱、不损失一点画质,纯赚 5-15% 性能。

3.1 发现过程

排查性能时打开任务管理器 → 性能 → 内存,发现内存运行频率只有 2666 MT/s——而内存条标称是 3600 MT/s。差出来的这 35% 带宽全部被浪费了,原因是 BIOS 默认按 JEDEC 标准频率运行,没有开启 XMP(内存超频预设)已核实。这在整机装机时尤其常见:装机商为了"点亮就行",默认是不开 XMP 的。

3.2 原理:模拟器是内存带宽敏感负载

Ryujinx 这类模拟器的 CPU 侧模拟(单线程翻译 + 大量内存读写)对内存带宽和延迟极其敏感推断。开启 XMP 后,模拟性能通常能直接提升 5-15%,而画面、画质、稳定性都不受任何影响——因为改的只是内存运行频率,让它回到出厂标称值,并不是激进超频。

3.3 BIOS 开启步骤

开机反复按 Del 进 BIOS,然后按主板品牌找:

  • 华硕:Advanced Mode → Ai Tweaker → Ai Overclock Tuner → 选 XMP I(或 XMP II)
  • 微星:OC → Extreme Memory Profile(XMP) → Enabled
  • 技嘉:Tweaker → XMP Profile → Profile 1

选好后 F10 保存重启。B760 主板 + 14600KF 的组合,3600 MT/s 的 XMP 属于官方支持范围内的常规操作。

3.4 开启后验证

进系统后再看任务管理器 → 内存,速度应显示 3600 MT/s。相比之前的 2666,内存带宽提升约 35%,这一步对后面 4K 60fps 的达成贡献不小。

3.5 配置细节:双通道 2×16GB 是最稳形态

2 条内存插 2/4 插槽(隔槽插)组成双通道,是 XMP 稳定开启的最经典配置。四条内存同时跑 3600 压力会大很多,兼容性问题也更多——如果将来升级内存,维持两条大容量比塞满四条更稳。

3.6 内存占用治理

XMP 开启后顺手处理另一件事:把内存占用从 86% 压到 75% 以下。两件事——关掉浏览器和后台大程序(浏览器动辄吃 3-6GB),把 Ryujinx 的 DRAM 设置从 12GB 改成 8GB。内存余量充足后,偶发卡顿和资源调度抖动都会明显减少。

第四章 4K 60fps 的正确路径——FSR 而非原生 4K

结论先行:在 14600KF + RTX 5070 这套配置上,原生 4K 必然超载,FSR 才是 4K 60fps 的正确打开方式。

4.1 一道算术题:为什么原生 4K 会失败

实测 1440p 分辨率下 GPU 占用 57%推断。分辨率从 1440p(约 369 万像素)到 4K(约 830 万像素),像素量是 2.25 倍,GPU 负载也要乘上去:57% × 2.25 ≈ 128%——超过 100%,必然爆。这就是直接上原生 4K 掉到 40 帧的根源,不是设置错,是算术上就跑不动。

4.2 FSR 方案原理

FSR 的思路是把渲染和输出解耦:游戏内部以约 1440p 渲染(负载和之前实测的 1440p 一样),再通过算法放大输出真 4K 信号。最终显示器收到的是完整的 3840×2160,观感接近原生 4K,而 GPU 负载维持在能跑 60 帧的水平。这是在画质和帧数之间唯一能两者兼得的路。

4.4 Ryujinx 侧锁定项复核

模拟器侧和第一章一致,再确认一遍:Resolution Scale 1x(最重要)、Vulkan、VSync Switch、DRAM 8GB、着色器缓存开。任何一侧有"再放大"的动作都会破坏 FSR 的负载平衡。

4.5 实测结果

这套配置下的真实负载:Avg 60 / Max 67,GPU 占用 57%、温度 50°C,CPU 单核满载推断。GPU 留有约 40% 余量,这些余量就是第五章画质上探的本钱。

4.6 前提条件:显示器必须是 4K 屏

这套方案的价值建立在 4K 显示器上。如果显示器是 1440p,把输出设成 4K 只是超采样,屏幕上看到的仍是 1440p,收益打折扣——这种情况直接用 1440p 输出配更高的画质档位更划算。

第五章 画质上探——把 GPU 余量花出去

GPU 还有 40% 余量,可以换回一些画质。每一项单独改、单独测,确认帧数稳了再加下一项。

5.1 Shadow Resolution:1024 → 2048

收益最大的一档。4K 输出下 1024 的阴影分辨率明显不够看,拉到 2048 后阴影边缘细腻一个档次,GPU 代价约 8%(57% → 65%),仍在安全区。

5.2 Render Distance:25000 → 20000

25000 是官方文档说明的默认值,不应增加,但降低是合法的性能旋钮已核实官方文档 ↗。降到 20000 给 CPU 模拟侧减负,远景细节出现时机略提前(画质几乎无感),换来更稳的帧率表现。

5.3 Force Level Of Detail:试开

开启后远景强制使用高模,4K 下远山、建筑细节提升明显。代价是增加 Draw Call(CPU 开销),帧数若出现恶化就立即关掉——这一项的容忍度因场景而异。

5.4 Dynamic Resolution:试关

关闭后内部渲染分辨率恒定,画质不再随场景负载波动。FSR 在兜底,所以帧数压力可控;代价是繁忙场景帧数波动会变大一点。画质优先就关,帧数优先就开。

5.5 FOV:50 → 55

观点纯个人偏好。视野广一点,3D 晕的概率也低一点,不喜欢的保持 50 即可。

第六章 最终成果、配置快照与经验总结

这套流程跑完,14600KF + RTX 5070 在王国之泪模拟上的最终形态是:4K 输出 + 稳定 60fps + GPU 仅 57% 的健康状态。

6.1 成果回顾

从起点(30 帧锁死、mod 假装在工作)到终点(Avg 60 / Max 67 / Min 42,GPU 50°C),全程没有降低任何画质档位,反而通过 FSR 获得了比 1440p 原生更好的观感。

6.3 天花板认知

14600KF + 5070 的极限就在这里,CPU 单线程是模拟器的架构级约束推断。模拟器的 CPU 侧模拟是单线程硬扛,和 GPU、分辨率、FSR 都无关——这台配置再往上压帧数,方向不在设置里。

6.4 教程外的心得

三条原则,比任何单条设置都重要:

  • 版本匹配 > 盲调参数:mod 版本、游戏版本、升级包版本三者对齐,比改一百次设置都管用
  • 先诊断后优化:任务管理器看清 GPU/CPU 谁是瓶颈,再决定动哪个旋钮;蒙头乱调只会离答案越来越远
  • 免费优化优先于画质牺牲:XMP 这种不花成本、不损画质的事,永远排在"降阴影""降分辨率"这类画质换帧数的操作之前
